# PHASE 18 — Template Recommendation

## Purpose

Phase 18 introduces a transparent, evidence-backed Template Recommendation system on top of Phase 17's Creative Preference Memory. It provides an advisory layer between template discovery and explicit user selection, helping users navigate to templates they historically prefer or have explicitly selected as favorites, without ever forcing a selection.

## Inputs

The recommendation engine takes the following structured inputs:
- `type`: The current creative format the user is trying to make (e.g. `post` or `reel`).
- `objective`: The current user-defined goal (e.g. `promotion`, `launch`, `engagement`).
- `vertical`: The business's vertical (e.g. `restaurant`).
- `businessId`: Identifies the tenant to load established preferences for.

## Eligibility and Filtering

Before recommending anything, the engine requests available templates from the `CreativeTemplateRegistry` using the user's current intent (`type`, `objective`, `vertical`).
- A template is eligible only if it is active.
- A template is eligible only if its `type` matches the requested `type`.
- A template is eligible only if it supports the requested `objective` (if specified).
- A template is eligible only if it supports the requested `vertical` (if specified).

**Filtering happens first.** If a template is generally preferred by the business but incompatible with their current objective or requested creative type, it is excluded and cannot be recommended. 

## Evidence Threshold

The recommendation engine solely consumes `CreativePreference` documents produced by Phase 17. 
- It respects Phase 17's established preference boundaries: A template must be explicitly marked as `preferred`, or have attained a `preferred` state through repeated positive evidence (e.g., approval threshold). 
- Avoided templates and templates lacking sufficient preference memory evidence are not recommended.

## Recommendation Logic

Recommendations are deterministic and require no AI calls:
1. Load eligible templates from the registry based on user intent.
2. Load established preferences for the business.
3. Determine evidence-backed candidates by intersecting `preferred` templates with eligible templates.
4. Sort candidates deterministically based on:
   - Explicit preferences (`explicit_user`) surface first.
   - Higher confidence scores.
   - Higher evidence counts.
   - Fallback to alphabetical sorting of template IDs.
5. The top candidate is set as the `recommended` template. The rest are returned as `alternatives`.

## Explanation System

Every recommendation is accompanied by an evidence-backed reason, directly derived from the Phase 17 memory, rather than generated by an LLM (preventing hallucination).
- Explicit preference: `"Because you marked this style as preferred."`
- Approval history: `"Because you've approved X [Template Name] creatives."`
- General preference memory: `"This template matches your recent creative preferences."`

## Selection UI and User Control Behavior

The recommendation operates entirely as a visual advisory in the existing Phase 7 Template Selection UI:
- **No Auto-selection**: Recommendations visually emphasize a specific choice but do not auto-advance or bypass user intent. 
- **See All Templates**: All non-recommended eligible templates are presented directly underneath as "Other options" or through full-list expansion.
- **Explicit Override**: User choice always wins. A user can select any eligible template, regardless of recommendation. If they select a template that preference memory marks as `avoided`, the system respects the explicit choice and proceeds with generation.

## Feedback Loop

Accepting a recommendation (i.e., selecting it in the UI) **does not count** as creative approval. 
- The selection is an intent signal, not a positive creative-quality signal.
- The `CreativePreference` evidence and confidence values remain completely unchanged upon recommendation acceptance.
- The only event that mutates preference memory remains explicit user feedback on the ultimately generated creative (Phase 16 -> Phase 17). This prevents self-reinforcing recommendation lock-in loops.

## Integrations
- **POST and Reel Support**: The single `recommendCreativeTemplates` engine dynamically supports both pipelines based on the passed `type` constraint.
- **Security**: Bound by `verifyBusinessAccess`. A client cannot fetch recommendations for another tenant's preferences, nor can they forge preference evidence or retrieve private templates.
- **Immutability**: Recommendation computes a transient snapshot. It never modifies `BusinessBrain`, `SavedStyle`, or the raw underlying `CreativePreference`.
